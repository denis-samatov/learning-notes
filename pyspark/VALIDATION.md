# Local recipe validation

The tested local profile is Python3.13.5 on macOS ARM64, Temurin JRE21.0.13+9, and `requirements-validation.txt` (PySpark4.2.1). The three original recipes `pyspark_collect.ipynb`, `pyspark_count_distinct.ipynb` and `pyspark_convert_map_to_columns.ipynb` executed successfully in fresh Python namespaces against an ephemeral Spark `local[1]` session. The same run checked nulls, empty input, schema and a UTC leap-day date, and parsed all19 notebooks: **5 tests passed in24.30s on2026-10-29**. The remaining16 notebooks were syntax-checked, not runtime-qualified. Historical notebook outputs were preserved.

Install the profile into an isolated venv, provide a compatible local JRE and verify actual Python/Java/package versions. This is an execution profile, not a generated cross-platform lock. [Official Spark installation documentation](https://spark.apache.org/docs/latest/api/python/getting_started/install.html) for the4.2 line requires Python3.10+ and Java17+. The tested [PyPI4.2.1 source archive](https://pypi.org/project/pyspark/4.2.1/) had SHA256 `d79b7c8ee41e66a9202fe6f600ca90b931ca571ae9dbdf31c58d2672e5102da0`. The official Adoptium macOS ARM64 JRE21.0.13+9 archive had SHA256 `225bab0a09491ef06835488cd942f5d2befa9a0410a2484f0c8bbcf7506ec09a`; it was extracted locally according to the [archive instructions](https://adoptium.net/installation/archives/), without a global Java installation.

Run `python -m pytest tests/ -q` for the default static gate; runtime cases are explicitly skipped unless opted in. For the tested runtime scope set `JAVA_HOME` to the extracted JRE Home directory, `PYSPARK_PYTHON` to the venv Python executable, `SPARK_LOCAL_IP=127.0.0.1` and `RUN_SPARK_TESTS=1`, then run `python -m pytest tests/ -q`. The fixture binds the driver to loopback, disables the UI and uses UTC, then stops the session. Use a temporary working directory for Spark-generated files. Ensure inherited `SPARK_REMOTE`/`SPARK_MASTER` settings do not point at another cluster. No remote cluster, model, corpus download or global environment setting was used during local qualification.

Driver collection is safe only when result cardinality is known to fit driver memory. Existing collect examples use four rows; dynamic map-key enumeration may collect unbounded keys on real inputs. Use distributed/select/explode transformations for unbounded data, constrain schema/cardinality before pivoting keys, and inspect explain plans rather than transferring the entire dataset to Python. A broadcast dictionary must also fit each executor; these tiny examples are not a load benchmark. Full19-notebook runtime compatibility, other platforms and distributed performance remain unqualified.
